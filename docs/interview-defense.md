# 面试防线速查（独立于简历，仅面试前自用，不可投递）

> 从 resume.md 拆出的面试口径。与简历表述保持一致是底线——简历写什么档位，面试就答什么档位。

## 一、托管系统必被追问的问题

1. **「为什么要做这个项目？」（背景/痛点——最高频第一问）** → 三段式作答：① 起源：做 Agent 开发时天天看 AI 跑单环节，单环节够强、串联全靠人——想法从工作现场长出来，不是拍脑袋；② 断裂点：环节衔接全靠人工搬运盯守 + 每次交接重新理解背景、上下文层层衰减；③ 定位判断：单环节提效是加法（省 10% 时间量级），流程托管改变交付模式，价值量级不同——所以做托管层而非加深单环节。
2. **「落地怎么保证？」** → 我是系统架构师：产出全部需求决策与架构设计、主导技术评审；落地由团队执行。被追问「怎么保证别人按你的架构落地」时答：技术评审机制 + 关键节点把关。
3. **「PoC 验证了什么？」** → 关键环节（方案生成、编码等）各自验证通过，串联开发中，非完整链路。与简历口径完全一致。
4. **「生态化会不会过度设计？」** → 诚实答：这是当前最大的架构风险，验证方式是先在一个具体场景（研发流程）打透，再抽象组装能力。补充动机：本质做的是「流程托管」的通用能力抽象，研发只是第一个场景——不是为生态化而生态化。
5. **「你说可组装，接入一个新场景具体要做什么？」（试金石）** → 两层作答。第一层（生态逻辑）：系统有原子能力层——审批、代码生成、方案生成等环节能力沉淀为标准化原子（独立输入/输出契约、独立可验证、跨场景复用、可被编排），场景是从能力池组装出来的产物，原子越沉淀越多、新场景组装成本越低，这是生态的复利逻辑。第二层（接入动作）：场景 = 环节序列 + 关卡规则 + 原子能力绑定三要素配置，新场景是写配置而非改代码（引擎不动）。举仓储出库例：审批原子声明货品 → 传感器/终端验证原子 → 消除人工信息传递。**必须主动说明**：多场景适配是设计目标而非已验证事实——目前只在研发场景设计落地。
6. **「架构分几层？」（简历已不写分层）** → 如被问到分层：我以关卡式管线 + 原子能力层组织系统，而非传统分层架构——原子能力层 + 环节关卡 + MCP 连接层。**不要**顺口编出「四层」——分层当时并未落实到设计里。
7. **「关卡式交接具体怎么做？」** → 上一环节产出先经质量关卡（自动校验/评审 → 人工确认位）再作为下一环节输入；关卡是错误隔离边界，也是人机切换点。
8. **「AI 出错了怎么办？」** → 三层：自动校验/评审拦截 → 回退重试（含最大重试次数与升级人工的阶梯）→ 关键节点人工确认位兜底。原子能力独立可验证，错误可精准定位到单个环节回炉，不拖整条链路。
9. **「AI 全流程托管，人会不会失控？」** → 信任三角作答：事前（关卡隔离错误，AI 产出过不了关到不了下游）+ 事中（所有节点流转支持 AI 驱动/人工推进双模，人可随时接管；各原子能力执行状态与产出均有可观测渠道，AI 在做什么随时可查）+ 事后（回退重试+升级人工阶梯）。一句话收尾：托管不是黑盒自动驾驶，是透明的人机共驾。
10. **「三个 AI 项目什么关系？」** → 精确口径：MCP 化是托管系统的前置工程（两层同构：托管按能力编排、MCP 按能力域划分）；三件套是相对独立的产品前端工作。共享 AI 工程化方法论。**不要**把三件套也包装成托管体系的一部分——被追问细节会露馅。

## 三、叙事口径

- **四年主线「先深度后广度、以深度为杠杆」**：实习 + 前端深耕（3 年）→ AI 深入（1 年）。被问「为什么转 AI」：不是逃离前端，是前端功底的杠杆变现——两条实证：① 会场搭建系统已支持 Agent 生成 DSL 驱动页面搭建（前端资产先成为 Agent 可操作的对象，转型是水到渠成）② 交互层优化的每个硬问题（流式卡顿、事件流设计）都是前端深水区问题。
- **会场搭建系统是「前端×AI」的衔接点**：第 2 年深耕期的前端项目即已接入 Agent（DSL 生成驱动搭建）——转型 AI 不是空降，是既有前端资产向 AI 时代的自然延伸。被问「你什么时候接触 AI」：会场项目时期就开始了（早于交互层/托管）。被问「为什么 Agent 能直接搭建页面」：因为整个系统是全 DSL 驱动——编辑的本质是改 DSL 配置，Agent 生成 DSL 与运营手工编辑走的是同一条链路，接入成本天然就低。
- **MCP 与托管系统的血缘口径**（替代旧「相对独立」表述中的 MCP 部分）：MCP 化是托管系统的前置工程——托管按能力编排，MCP 按能力域划分，两层同构；发起顺序是先有托管构想、再发现需要工具层支撑。三件套仍是相对独立的产品前端工作。被问「三个 AI 项目什么关系」时按此精确口径作答，不再笼统说「相对独立」。
- **MCP 化「为什么按能力域划分」**：托管平台按能力编排流程，MCP 工具层同构地按能力域划分——编排的能力即 MCP 暴露的能力，粒度一一对应。被问「为什么不是按系统划分」：按系统划分对 Agent 侧不友好（Agent 想的是「我要发个审批」，不是「我要调审批平台的哪个接口」），且与托管编排层粒度错位。
- **4 年经验口径**：简历统一写「4 年经验」，不特别标注实习；工作经历首条如实保留实习条目，保证 4 年时间轴可加总核对。被问入行起点或背调时如实说明：首年为前端实习，方向连续、无跨行折损。
- **交互层（原「三件套」）的深挖口径**：卡顿三类症状 + 三种解法一一对应——① 高频 token 打满主线程 → 时间窗口批量提交（攒帧渲染，牺牲即时性换流畅）② 长历史越用越卡 → 视口分级渲染（可视区实时、视口外骨架降级）③ 富内容流式中反复重解析 → 延迟升级（流式纯文本、完成后再解析代码块/图表）。每条都能讲「症状→方案→取舍」三层。会话重放基于统一事件模型（事件流天然可回放），被问「怎么实现的」：回放=事件序列重演，渲染器复用实时链路的那套分发机制。没有调试监控面板——被问「怎么调试 Agent」答会话重放，不要现编「调试面板」。被问「为什么 SSE 不 WebSocket」：单向流式推送场景 SSE 足够且更轻——**如实际用的不是 SSE 则按真实情况讲**。项目名已定为「Agent 交互层优化」——若面试官问「三件套是什么」按新项目名答，不要沿用旧称。
- **MCP 项目不报具体数字**：被追问规模时诚实回答「团队级在用、未做量化统计」，随即转讲「一次封装、多方复用」的架构价值。
- **差异化备选口径**（被问「比其他候选人强在哪」时打）：会做 Agent 交互层的前端工程师 × 会做 Agent 基建的前端出身工程师——双栈交叉地带市场供给稀缺。简介走事实直陈式、未显式写对比，此牌留作口头。
- **项目排序逻辑**（面试官若问「项目按什么排的」或自我介绍选讲顺序）：按与目标岗位的证据强度排——三个 AI 项目（托管/MCP/交互层）是主锚点 → 会场搭建系统是前端×AI 的衔接证据（事业群级+Agent 生成 DSL）→ 模板编辑器/独立站是独立交付深度与广度佐证 → 桌面平台是全栈闭环兜底。自我介绍按此顺序讲，先锚点后佐证。
